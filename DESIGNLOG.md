# Design log

This log records consequential implementation decisions, their evidence, and the tradeoffs that future scanner work must preserve.

## 2026-08-04 — Require exact Go object, principal, query, and effect closure

**Decision.** Add a separate typed Go CWE-639/CWE-862 model for object-level authorization at the standard-library `net/http` to `database/sql` boundary. Preserve request source, object identifier, fixed query and placeholder role, exact typed receiver, wrapper argument, authenticated-principal provenance, candidate authorization control, selected data, and protected read or mutation effect as distinct evidence. Parameterized SQL prevents grammar injection; it does not authorize the object selected by a bound value.

**Why.** OWASP API1:2023 requires every endpoint receiving an object ID and acting on the selected record to validate that the logged-in principal may perform the exact action on that object, whether the identifier is an integer, UUID, or string and whether the effect is read, update, or delete. Go documents `QueryRow`/`QueryRowContext`, later `Scan`, and the separation between fixed query text and placeholder arguments, including multi-predicate examples. The current CodeQL Go query index and published gosec rule list do not expose a dedicated object-level authorization query. A precise standard-library lane therefore adds material coverage without conflating BOLA with SQL injection, endpoint authentication, UUID opacity, or generic business-logic suspicion.

**Type, source, and query boundary.** Require exact default or explicit `net/http` and `database/sql` imports and a typed `*http.Request` plus proven DB, Tx, or Conn receiver. Accept query, form, path, and header object identifiers and preserve bounded assignments, fixed query constants, direct calls, inferred handles, and one unique same-package string wrapper. Parse equality predicates with `?`, `$n`, `:name`, or `@name` placeholders, including exact `sql.Named` values. Treat `id`, `key`, `uuid`, and their suffixed column forms as object keys while keeping owner, tenant, account, organization, customer, principal, shop, user, and workspace keys as security dimensions. Dynamic queries, fixed/reassigned identifiers, immutable server-owned maps, untyped lookalikes, duplicate wrappers, comments, and strings fail closed. Shared call parsing now tracks quote and escape state so commas inside interpreted or raw Go string arguments do not split callable roles.

**Principal, control, and effect boundary.** A principal is trusted only when it comes from `Request.Context().Value` under a principal-related server-owned key and remains non-reassigned. A same-query security predicate is recorded as `principal-bound-object-query` only when its exact placeholder argument has that provenance, including across a unique wrapper; a similarly named string, header, form, path, or query argument is not control evidence. A returned owner-like value can produce `post-lookup-principal-check` only when it is scanned, compared with the context principal, and a fail-closed return precedes disclosure. A read requires exact `QueryRow` construction, `Scan`, and response use of scanned data through writer, `io`, `fmt`, or JSON encoder shapes. `UPDATE` and `DELETE` through exact `Exec` variants are immediate mutation effects. Generic success text, lookup without scan, checks after disclosure, and authorization for another object are excluded.

**Executable and regression evidence.** Add paired Go 1.26 modules with deterministic offline `database/sql/driver` witnesses. The positive takes a path-selected victim invoice through one wrapper into `SELECT secret FROM invoices WHERE id = ?`, scans it, and proves disclosure of `victim-signing-key`. The control preserves the handler, wrapper, object ID, query dispatch, scan, and response but binds `account_id` to a context-derived authenticated account. Its witness proves an attacker account receives no victim record while its owned invoice still returns normally. Fourteen focused tests cover the perfect manifest, exact cross-file path and evidence locations, every typed request family, read closure, generic-response rejection, update/delete effects, context-only controls, positional/numbered/named placeholders, exact imports and typed receivers, fixed queries, DB/Tx/Conn and inferred handles, fail-closed post-lookup checks, immutable maps, ambiguity, wrapper principal provenance, reassignment, comments/strings, and reviewer guidance. ## 2026-08-04 — Require Go template source to reach execution and retain capabilities

**Decision.** Add a separate typed Go CWE-1336 model for request-controlled source interpreted by the exact standard-library `text/template` package. Preserve typed request source, import identity, source argument zero, immutable source selection, builder and parsed-object identity, `FuncMap` registration, execution data, actual `Execute` or `ExecuteTemplate` closure, wrapper propagation, and concrete capability as distinct evidence. **Why.** Go documents `Template.Parse` as parsing its string argument into template bodies and `Template.Funcs` as installing functions used by parsing and execution. The current CodeQL Go query index has no server-side template-injection query. HTML escaping does not consume Go's brace-delimited directive grammar, and fixed-template output encoding is a separate browser-context question. ## 2026-08-04 — Preserve Go path taint through normalization and prove rooted controls

Preserve source, import identity, path construction, exact argument and source/destination role, filesystem effect, wrapper propagation, candidate controls, authorization, runtime/platform behavior, and concrete impact as distinct evidence. ## 2026-08-04 — Extend Go process closure through manual state and direct dispatch

Preserve package identity, source, executable selection, argv roles, mutable object or slice state, alias semantics, execution timing, command-specific interpretation, controls, and concrete effect as separate evidence. Manual command state requires later execution on the same object; low-level functions dispatch at the call itself.

A pointer alias shares later mutations; a copied value retains independent scalar fields, matching Go assignment semantics closely enough to avoid treating a later `Path` write on the original as a write to the copy. ## 2026-08-04 — Separate Go command construction, argument roles, and process execution

## 2026-08-04 — Preserve GORM generics signatures and callback execution closure

**Decision.** Extend the existing exact `gorm.io/gorm` CWE-89 model through the generics API without treating it as a spelling variant of the traditional `*gorm.DB` API. Prove `gorm.G[T](db)` from an exact typed database handle, track the documented generic interfaces and aliases, preserve context, grammar, values, expressions, builder state, callbacks, and finishers as separate evidence, and keep the traditional signatures unchanged.

**Why.** GORM has promoted its generics API since v1.30. Its type families materially change the call contract: `Exec` places context before SQL; `Raw` returns an execution interface; query finishers take context and return typed results; `Count` accepts a structural column after context; joins and preloads accept typed builder callbacks; and `Set` returns specialized create/update interfaces. The current upstream source uses DryRun statement construction for `Build`, so materialization is not database dispatch. The inspected CodeQL extension groups modern and legacy GORM receivers around traditional `DB` methods but does not describe `G[T]`, the generic interfaces, their context-first positions, or callback closure. Reusing traditional argument offsets would miss immediate generic SQL, invent inline-condition findings on typed result methods, and confuse join metadata with raw SQL. An exact host model can close those gaps while retaining stronger construction-to-execution precision.

**Parser and type boundary.** Extend the shared Go call parser to consume one balanced generic type-argument list between a callable name and its opening parenthesis, leaving the parsed callable name unchanged. Typed receiver discovery opts into generic type arguments explicitly; non-generic models retain their previous declarations. ## 2026-08-03 — Recover exact coverage aliases without guessing

**Decision.** When a model-authored coverage surface omits or corrupts `disposition`, accept `outcome` or `status` only if its value is an exact member of the canonical coverage-disposition set. Prefer `outcome` over `status`, preserve an already-valid `disposition`, and continue to force `needs_follow_up` plus partial coverage for every absent, descriptive, or otherwise ambiguous value.

**Why.** The first acceptance scan from the inspected Linux release tarball found and fully traced the intended multi-hop OkHttp SSRF, but the model wrote `status: "no_issue_found"` for `pom.xml` without the schema-required duplicate `disposition`. **Consequence.** This is a syntax recovery, not a security conclusion. The finalizer may normalize an exact canonical duplicate field, but it must never translate prose such as “looks clean” into a closed review or use an alias to override a valid canonical `disposition`.

## 2026-08-03 — Prepare directories, never evidence

**Decision.** Before model execution, the trusted host creates a fixed private directory skeleton for context, six stable deep-discovery pass IDs, coverage, validation, reconciliation, attack-path, and findings artifacts.
